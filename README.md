# warp-xray-generator

Одностраничный генератор конфигов **Xray** для **Cloudflare WARP** с обфускацией, обходящей блокировку WireGuard российским ТСПУ.

Каждый посетитель получает свежие креды WARP и **уникальный обфусцирующий пакет** — два конфига, выданных подряд, не совпадают ни одним байтом шума. Готовый конфиг отдаётся по ссылке-подписке, которую понимают мобильные клиенты.

Продолжение исследовательского проекта [awg-to-xray-warp](https://github.com/SolverNA/awg-to-xray-warp), где были найдены и проверены в бою сама схема обфускации и корректный отпечаток пакета.

---

## 1. Как это работает

WireGuard режется ТСПУ по сигнатуре первого пакета рукопожатия. AmneziaWG решает это своими junk-полями, но **в Xray их нет вообще** — там есть только `noises` у outbound'а `freedom`.

Схема обхода:

```
outbound "warp"  (protocol: wireguard)
   └── streamSettings.sockopt.dialerProxy → "noise-out"
outbound "noise-out"  (protocol: freedom)
   └── noises: [ QUIC Initial 1252 байта, затем 8 × rand ]
```

Xray отправляет шумы **один раз при создании UDP-сокета**, перед рукопожатием. ТСПУ видит валидный QUIC Initial и перестаёт считать поток вайргардом.

Ключевой результат исходного проекта: ТСПУ **разбирает QUIC Initial по RFC 9001**, а не держит список байтовых сигнатур. Поэтому пакет обязан быть настоящим — с корректными ключами, AEAD и защитой заголовка. Поддельный не проходит.

### Отпечаток

Генерируемый ClientHello даёт JA4 `q13d0310h3_55b375c5d22e_cd85d2d88918` — он совпадает с перехваченным Chromium целиком. Всё, что влияет на отпечаток, зафиксировано; всё остальное (SNI, DCID, номер пакета, ключ key_share, порядок расширений, значения транспортных параметров) меняется при каждой генерации.

Это два разных требования, и их важно не перепутать: **отпечаток обязан быть одинаковым у всех, содержимое — разным у каждого.** Одинаковый отпечаток делает нас неотличимыми от браузера; разное содержимое не даёт вычислить нас по повторяющемуся байтовому блоку.

## 2. Архитектура

```
lib/quic-initial.js   генератор QUIC Initial (порт с Python)
lib/ja4.js            расчёт JA4 — используется тестами
lib/build-config.js   сборка JSON-конфига Xray
lib/warp.js           регистрация аккаунта в Cloudflare
api/generate.js       регистрация + генерация + запись в хранилище
api/sub/[id].js       отдача подписки, выбор формата по User-Agent
public/               одностраничный интерфейс
test/                 тесты
```

Хостинг — Vercel, серверные функции на Node. Генерация целиком серверная: регистрация в Cloudflare из браузера невозможна из-за CORS, а конфиг всё равно должен попасть в хранилище, чтобы его забрал клиент по ссылке-подписке.

Криптография — только встроенный `node:crypto`, внешних зависимостей нет.

### Срок жизни

Конфиг живёт на сервере **5 минут**, на странице идёт счётчик. Дальше ссылка отдаёт 404.

Отсюда следует, что ссылка — **одноразовый канал доставки, а не живая подписка**. Конфиг, уже импортированный в приложение, продолжает работать; перестаёт работать только повторное обновление подписки. Поэтому `profile-update-interval` выставляется заведомо большим, а на странице написано «импортируй сразу».

### О приватности — честно

Пока конфиг лежит в хранилище, **приватный ключ WireGuard находится на сервере**. Иначе подписку сделать нельзя: клиент забирает конфиг именно оттуда. Пять минут вместо постоянного хранения снижают риск, но не убирают его. Кто хочет полной приватности — пусть генерирует конфиг локально через [gen-warp-config.py](https://github.com/SolverNA/awg-to-xray-warp).

## 3. Совместимость клиентов

Подписка отдаётся как **массив полных конфигов Xray** (`content-type: application/json`). В каждом элементе обязаны быть ключи `remarks`, `inbounds`, `outbounds` и `routing` — без `routing` v2rayNG не опознаёт подписку.

| Клиент | Ядро | Статус |
|---|---|---|
| v2rayNG | xray | Исполняет дословно — подтверждено исходниками |
| Throne | sing-box + xray | Исполняет дословно, включая цепочки dialerProxy — подтверждено исходниками |
| Happ | xray | Передаёт конфиг в ядро как есть — по документации |
| v2rayN (десктоп) | xray | Поддерживает полные конфиги с версии 6.40 |
| v2rayTun | xray + AWG | JSON-подписки поддерживает, дословное исполнение **не подтверждено** — нужен живой тест |
| Streisand | xray | Классифицируется как xray-клиент, дословное исполнение **не подтверждено** — нужен живой тест |
| Hiddify, sing-box (SFA/SFI/SFM), Karing | sing-box | **Непереносимо в принципе** |
| Clash, Mihomo, Stash, Shadowrocket | clash/своё | **Непереносимо в принципе** |

Про sing-box и Clash смягчать нечего: в этих ядрах **нет самой концепции `freedom` с `noises`**, а у WireGuard-эндпоинта sing-box нет опций обфускации вообще. Наш сценарий туда не переносится ни в каком виде — ни конвертацией, ни костылями.

### Ссылки импорта

```
happ://add/<url>
v2raytun://import/<url>
v2rayng://install-config?name=<имя>&url=<url>
```

У Throne URL-схемы нет — только копирование ссылки вручную. Ссылка подписки делается **без query-параметров**, иначе схемы вида `?url=` ломаются на `&`.

## 4. Интерфейс

- Кнопка «Генерировать».
- Шторка «Редактировать настройки», по умолчанию свёрнута: все поля доступны для правки, у генерируемых полей — своя кнопка «перегенерировать».
- Кнопка «Обновить конфиг» — меняет все изменяемые креды разом.
- После генерации: ссылка-подписка, счётчик живости, копирование в буфер, QR-код, кнопки импорта в приложения.

QR-код содержит **ссылку**, а не конфиг. Это не декоративное решение: конфиг весит около 4 КБ (один шум в hex — это 2504 символа), а предел QR-кода — 2953 байта. Сырой конфиг в QR не помещается физически.

## 6. Известные ограничения

- Эндпоинт зафиксирован: `162.159.192.1:500`. Это единственный адрес из проверенных, который живёт в подсети WARP, а не в подсети API Cloudflare.
- SIP-профиль обфускации не поддерживается намеренно: на мобильных сетях режется сам признак «UDP на порт 500 с SIP-подобной нагрузкой», независимо от содержимого пакета.
- Все регистрации уходят в Cloudflare с одного egress-адреса Vercel. При заметном трафике упрёмся в лимит по IP.
- Версия API Cloudflare `v0i1909051800` — слепок клиента 2019 года. Работает, но однажды её отключат.
